01

今日やること

この3つだけ
やること 1

重すぎる画像を1枚、差し替える

−225KB

名称未設定のデザイン.png が 246KB あります。以前は31KBでした。いまページで最も重いファイルで、JavaScriptより大きい状態です。実際は150px幅ほどで表示されているのに、1024px幅で配信されています。

  1. メディア → ライブラリ で 名称未設定のデザイン を探し、開いて「ファイルをダウンロード」で保存します。
  2. ブラウザで squoosh.app を開き、その画像をドラッグ＆ドロップします。
  3. 右側の 「Resize」にチェックを入れ、Width を 300 にします。
  4. 右下の形式を WebP（文字が入っているなら PNG のままでも可）にして、ダウンロードします。
  5. メディア → 新規追加 でアップロードし、トップページの編集画面で差し替えます。
  6. 保存 → Purge Everything。
できたらこうなる
246KB → 20KB前後。モバイルのページ容量が 944KB → 790KB前後に下がります。
やること 2

トップの大きな画像を「先に読む」設定にする

LCP −1秒前後

LCP（表示完了）の対象は Hopping-Daikoku-PA①.jpg です。ファイル自体は29KBと軽く、サイズに問題はありません。読み込む順番が後回しになっているだけです。実測3回が 6.98 / 3.46 / 3.73秒 とばらついているのがその証拠です。

  1. 設定 → EWWW Image Optimizer を開きます。
  2. 「Above the Fold」の数値を 2 にします（前回設定済みなら、そのままで構いません）。
  3. 同じ画面の 「Exclusions」欄に、次の1行が入っているか確認します。無ければ追加してください。
    p-mainVisual__img
  4. SWELL設定 → 高速化 を開き、遅延読み込み（Lazy Load）の設定があればオフにします。EWWW と二重に動いているためです。
  5. 保存 → Purge Everything。
できたらこうなる
3回の実測値のばらつきが消えて毎回ほぼ同じ数値になり、LCP が 3.73秒 → 2秒台前半まで下がる見込みです。
効かなかったら
手順4の SWELL 側の遅延読み込みが原因である可能性が高いです。その場合は状況を教えてください。次の手を出します。
やること 3

Purge して、再計測する

確認
  1. dash.cloudflare.com → 81drive.com → 左メニュー Caching → Configuration → Purge Everything。
  2. 1〜2分待ちます。
  3. GitHub の jdmpride1-debug/81drive → 上部タブ Actions → 左の Performance audit (US) → 右の Run workflow。
  4. 5分ほどで完了します。結果を私に聞いてもらえれば読み解きます。

やること1と2をまとめてやってから計測して構いません。どちらも確実に効く作業なので、切り分けは不要です。

−173KB

あとで B

下のほうにある旧PNG 2枚

−数百KB
