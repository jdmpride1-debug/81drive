04

今すぐやるべきこと

1

Google タグの重複を解消する

−1.52秒 / −345KB

タグ設定現在、同じ計測 ID のタグが3本読み込まれています。

173KB  gtag/js?id=GT-TX9NK383
172KB  gtag/js?id=GT-TX9NK383&cx=c&gtm=4e6992   ← 今回増えた分
115KB  gtm.js?id=GTM-WFGD8X5Q
─────
460KB  同一 ID を3重に計測

2本目は GTM 経由で読み込まれた GA4 タグで、1本目のテーマ／プラグイン側の直接埋め込みと重複しています。GTM に一本化し、テーマやプラグインの直接埋め込みを削除してください。

これは現在モバイルの最優先改善項目です。Lighthouse は「未使用の JavaScript の削減」で 1.52秒 の短縮を見込んでいます。サードパーティ JS はメインスレッドを 360ms 占有しており、TBT と TTI が悪化した直接の原因でもあります。

2

残り4枚の PNG バナーを WebP 化する

−2.0MB

設定のみモバイル用の1枚は軽量化されましたが、デスクトップ用の 1024px 版が手つかずです。

633KB  DAIKOKU-TOUR バナー-1024x576.png
560KB  JDM-TOUR バナー-3-1024x576.png
545KB  image-1-1024x576.png
537KB  image-1024x576.png

デスクトップの総容量が 2,282KB → 2,995KB に増えており、「巨大なネットワークペイロード」として警告が出ています。EWWW の WebP 変換を全サイズに対して再実行してください。

3

メインビジュアルを優先読み込みにする

LCP 改善

テーマ編集前回から変わっていません。モバイルの初回計測では LCP が 6,210ms に振れており、この画像の取得タイミングが不安定です。fetchpriority="high" の付与と遅延読み込みからの除外は、TTFB が解消された今こそ効果が出ます。

4

vary: User-Agent を外す

hit 率向上

設定のみキャッシュ自体は効き始めましたが、このヘッダーが残っている限り User-Agent 文字列ごとに別エントリが作られます。今回の計測では age: 3017（約50分前のキャッシュ）に当たりましたが、実ユーザーの端末が多様なほど MISS が増えます。

06

補足

TTI の悪化について：モバイルの TTI が 6.57s → 7.31s と悪化していますが、これは Rocket Loader を外したことで JS が本来のタイミングで実行されるようになった影響と、タグが1本増えた影響の合算です。なお TTI は Lighthouse 12 のスコア計算には含まれていません（FCP・SI・LCP・TBT・CLS で算出）。体感速度により近い SI は 2.44s → 2.03s と改善しているため、全体としては前進しています。タグ重複を解消すれば TTI も戻ります。

計測のばらつき：モバイル LCP の3回の値は 6.21s / 2.48s / 2.50s で、初回のみ大きく外れています。中央値の 2.50s を採用していますが、この振れ幅自体がメインビジュアルの優先読み込み（施策3）が未実施であることを示しています。

計測は Actions → Performance audit (US) からいつでも再実行できます。変更を加えたら再度実行してください。
