原因は確定しました

07:15 のレスポンスヘッダー 
age: 8016                                    ← 2時間13分前のコピー
last-modified: Sat, 12 Sep 2026 05:02:22 GMT  ← 画像入れ替え前の版
cache-control: max-age=14400                     ← 4時間保持される
cf-cache-status: HIT                             ← キャッシュから配信
cf-ray: a39d1fc81a1161ad-ORD

age: 8016 は「このコピーは 8,016秒（2時間13分）前に保存された」という意味です。キャッシュを削除していれば、ここは 0 に戻ります。

さらに last-modified は 05:02。画像の入れ替えが反映されたのを最初に確認したのが 06:23 なので、配信されているのは入れ替え前のページで確定です。

結論

Cloudflare のキャッシュ削除（Purge Everything）が実行されていません。サーバー側の問題でも、ページ更新の失敗でもありません。削除すれば即座に解決します。

新旧が入れ替わって見えたのは、Cloudflare が世界中の拠点ごとに独立したキャッシュを持つためです。入れ替え後に新しく取得した拠点は新しいページを、05:02 の版を保持したままの拠点は古いページを返します。vary: User-Agent がこれをさらに分割し、同じ拠点でもパソコンとスマホで別々のコピーになります。

仕組みの説明

LCP は「最初の画面に見える一番大きい要素が表示されるまでの時間」です。今回軽くしたバナー4枚はスクロールした先にあるため、LCP の計測対象ではありません。

LCP の対象は一貫してトップのメインビジュアル（メインビジュアル用.jpeg）です。この画像は「後回しでいい画像」として扱われているため、読み込みが遅れます。

STEP 3

トップの大きな画像を「最優先」で読み込ませる

表示の安定化設定で対応可
なぜ必要か：トップページの一番大きい画像（メインビジュアル）が、「後回しでいい画像」として扱われています。そのため読み込みが遅れ、計測3回のうち1回は表示に 7.38秒 かかりました（他2回は2.5秒）。このばらつきがまさにその証拠です。「最初に見える画像は後回しにしない」と指定すれば安定します。

EWWW の遅延読み込み機能から、この画像だけを除外するのが一番安全な方法です。

  1. 設定 → EWWW Image Optimizer を開きます。
  2. 「Lazy Load」（遅延読み込み）の設定欄を探します。「Easy Mode」にある場合と、「Advanced」の中にある場合があります。
  3. その近くにある「除外するもの」「Exclude」という入力欄に、次の1行を貼り付けます。
    p-mainVisual__img
  4. 保存します。
  5. SWELL側にも遅延読み込み設定があります。SWELL設定 → 高速化 を開き、「遅延読み込み」の項目に除外設定があれば同じ文字列を追加してください。
補足
遅延読み込みのプログラム（lazysizes）が EWWW と SWELL で2本読み込まれています。どちらか片方で十分なので、SWELL設定 → 高速化 で遅延読み込みをオフにして EWWW 側に任せると、さらに軽くなります。ただし STEP 1・2 を終えてから、1つずつ試してください。
できたらこうなる
計測3回の LCP のばらつき（7.38s / 2.54s / 2.53s）が揃い、毎回ほぼ同じ数値になります。
STEP 4

外部サーバーへの接続を前倒しする（preconnect）

−0.33秒1行追加
なぜ必要か：Googleや口コミサービスなど外部のサーバーから読み込むファイルがあります。ブラウザは「必要だとわかった時点」で接続を始めるため、その分だけ待ち時間が生まれます。「あとでこのサーバーを使うよ」と先に伝えておくと、その待ち時間が消えます。Lighthouse の試算で 0.33秒 の短縮です。
  1. SWELL設定 → 一般 の中にある「<head>内に出力するコード」の入力欄を開きます。（STEP 1 で確認した欄と同じ場所です）
  2. 次の3行をそのまま貼り付けて保存します。
<link rel="preconnect" href="https://www.googletagmanager.com" crossorigin>
<link rel="preconnect" href="https://cdn.trustindex.io" crossorigin>
<link rel="preconnect" href="https://static.cloudflareinsights.com" crossorigin>
順番に注意
STEP 1 を先に終わらせてください。STEP 1 で GTM を外した場合、1行目は不要になります。
STEP 5

Cloudflareのキャッシュを消す（毎回の仕上げ）

30秒
なぜ必要か：Cloudflare は古いページのコピーを持っています。設定を変えてもコピーが残っていると変更が反映されません。「直したのに変わらない」の原因はほぼこれです。STEP 1〜4 のあと毎回実行してください。
  1. dash.cloudflare.com にログインします。
  2. サイト一覧から 81drive.com を選びます。
  3. 左メニューの 「Caching」→「Configuration」を開きます。
  4. 「Purge Everything」（すべて削除）ボタンを押し、確認ダイアログでもう一度押します。
  5. 1〜2分待ってから、スマホやシークレットウィンドウでサイトを開いて確認します。
ついでに直せること
現在キャッシュの有効期間が 4時間（max-age=14400）です。今回の計測はちょうど期限切れの瞬間に当たりました（cf-cache-status: MISS）。4時間ごとに1人目の訪問者だけが遅くなる状態なので、Caching → Configuration → Browser Cache TTL や Cache Rule の Edge TTL を1日以上に伸ばすと安定します。更新時は上の Purge を実行すれば即座に反映されます。
